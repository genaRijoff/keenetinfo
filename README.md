# keenetic-info (kss)

Сводка роутера Keenetic / Netcraze в терминале: модель, прошивка, процессор,
все датчики температуры, память, диски, Wi-Fi, порты, интернет, клиенты.

Переработка [pumbaX/keenetic-info](https://github.com/pumbaX/keenetic-info).

Работает на KeeneticOS 4.x, 5.0, 5.1 и 5.2 (alpha), в том числе с токенами RCI,
которые появились в 5.2. Архитектуры mips, mipsel, aarch64. Нужен Entware.

## Установка

```sh
curl -fsSL https://raw.githubusercontent.com/genaRijoff/keenetinfo/main/install.sh | sh
```

curl установщик поставит сам, jq — по возможности (без него тоже работает).

## Команды

| Команда | Что делает |
|---|---|
| `kss` | компактная сводка |
| `kss -f` | подробная сводка |
| `kss token` | статус токена RCI (5.2+) |
| `kss token new` | выпустить токен заново |
| `kss token del` | отозвать токен kss на роутере |
| `kss debug` | сырые ответы RCI и /sys в `/tmp/kn-info-debug` |
| `kss update` | обновить скрипт |
| `kss uninstall` | удалить kss и отозвать токен |
| `NO_COLOR=1 kss` | без цвета |

Подробный вид по умолчанию:

```sh
echo 'KN_INFO_STYLE=full' > /opt/etc/kn-info.conf
```

Приоритет: флаг > переменная `KN_INFO_STYLE` > конфиг > компактный вид.

## Датчики

Показывается всё, что есть на конкретном роутере:

- процессор и другие зоны ядра (`/sys/class/thermal`) — CPU, DDR…
- радиомодули Wi-Fi 2.4 / 5 / 6 ГГц — из RCI;
- LTE-модем — из RCI, вместе с уровнем сигнала;
- NVMe, диски (drivetemp), SFP и прочее из `/sys/class/hwmon`.

Если у радиомодулей одна температура (оба диапазона на одном чипе, как у MT7981),
она показывается одной: `Wi-Fi 46°`.

Цвет: до 55° зелёный, 55–69° жёлтый, от 70° красный. Если датчиков много,
строка переносится по ширине терминала.

## KeeneticOS 5.2: токены RCI

С 5.2 каждый запрос к локальному RCI (`127.0.0.1:79`) без токена пишет в журнал
`obsoleted unauthenticated loopback RCI access will be removed soon`.
Доступ без токена обещают убрать, и тогда старые скрипты получат 401.

Что делает kss:

- на 5.2+ при первом запуске выпускает себе токен через `ndmc`
  (`authentication token generate kss`) — локально, без пароля;
- хранит его в `/opt/etc/kn-info.token` (права 600) и шлёт в заголовке `X-NDMA-TKN`;
- если токен отозвали (403, `0x2312`), выпускает новый и снимает старый;
  чужие токены (xkeen, awg-manager) не трогает;
- на 4.x–5.1 токен не нужен, всё как раньше.

## Если что-то не так

- `kss debug` — соберёт ответы RCI и данные /sys в `/tmp/kn-info-debug`
  (токена там нет). Приложите к issue.
- `RCI не отвечает … код 401` — `kss token new`.

## Что нового в 3.0.0

- Работает на KeeneticOS 5.2: токены RCI.
- Все датчики температуры, а не только CPU и Wi-Fi 2.4/5.
- Компактный вид по умолчанию, подробный — `kss -f`.
- Wi-Fi по всем радио, включая 6 ГГц; сигнал LTE; скорость портов; соединения.
- Примерно в 15 раз меньше процессов за запуск — заметно быстрее на MIPS.
- jq необязателен: без него результат тот же.
- `kss uninstall`, проверка скачанного файла при `kss update`.

Проверено на стенде: реальные ответы RCI с 5.1.3 и эмуляция 4.x и 5.2 с токенами.
С живых роутеров на 5.2 — ждём отзывы.
